# Granite backends, the model picker, and an interactive desk door

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Tasks are bite-sized with their own test cycles; checkbox steps track progress.

**Goal:** Pluggable LLM backends (IBM Granite via local Ollama, alongside Claude) selected per surface like Cursor's model picker — powering the Atlas reasoner and, staged, the workforce roles — with the choice made at TUI startup alongside the Alpaca posture, switchable live via `/model` + SETTINGS, plus in-TUI Alpaca credential entry and a test-connection verdict.

**Architecture:** The owner owns everything: a backend protocol (`available() -> (bool, reason)`, `complete(...)`) with `OllamaBackend` (HTTP to localhost:11434, no SDK) and `ClaudeCliBackend`; per-surface `llm_config` state (`reasoner`, `workforce`) persisted beside `desk_mode.json`, seeded from env, set via `POST /api/llm`, served on `/api/tui`, with a `GET /api/llm/backends` catalog of what is actually reachable (offered-not-enforced — the owner is the one validator). The Rust client renders and picks, never resolves. The reasoner (the user's atlas-as-llm step 3) runs behind a flag with the deterministic path as fallback, both writing decision rows. Alpaca credentials get one owner route that reuses `alpaca_auth`'s secret hygiene; the TUI gets a masked form and a startup modal combining desk mode + model + credentials.

**Tech stack:** Python (owner: stdlib/urllib or httpx for Ollama — match repo style), Rust (ratatui client patterns already established: picker/typing/confirm/KEYMAP).

## Global Constraints

- The Rust-client rules from the workstation branch bind: time-as-data, theme-only, `Some("")` absent, allocated-rect floors, KEYMAP scrape, views-never-IO, `#[cfg(feature = "operator")]` for anything write-capable, both matrix legs green per task.
- **Governance:** `REQUIRED_CLAUDE_ROLES = {"referee"}` — the approval gate never runs on an experimental backend (extends `REQUIRED_DEEP_ROLES`' precedent in `model_routing.py:48`). `check_startable` and every deterministic gate stay untouched. The reasoner flag's dual-write comparison condition from `planning-docs/2026-07-31-atlas-as-llm.md:174-176` is honored.
- **Secrets:** credential values never appear in logs, tracebacks, command history, toasts, or reprs — `alpaca_auth.py`'s hygiene (`:37-41`, `:44-88`) is the single writer/reader; the Rust client masks input and sends once over the local socket.
- **Offered, not enforced** (`cmd.rs:336-339` rule): the TUI offers only what `GET /api/llm/backends` serves; the owner validates every choice; unavailable backends appear WITH their reason, never hidden, never silently substituted.
- No silent model fallback: a selected backend that stops answering degrades loudly through the existing `DEGRADED`/refusal paths with the reason on screen.

## Phases and tasks

### Phase A — the backend layer (owner)
- **A1 — backend protocol + Ollama + Claude probes.** `qlab/operator/llm_backends.py`: `LlmBackend` protocol (`name`, `available() -> tuple[bool, str]`, `complete(system, user, model, max_tokens) -> str`, `models() -> list[str]`); `OllamaBackend` (GET /api/tags for availability+pulled models — absence [connection refused] vs error [bad response] distinguished à la `AlpacaAuthError`; POST /api/chat for completion; fail loud on missing model with the pull command in the message); `ClaudeCliBackend` (wraps `resolve_claude_executable` + one-shot `claude --print`; models = the routing tier names). Tests: mock HTTP server, both absence/error paths, no network.
- **A2 — llm_config state + routes.** Copy the fast-mode chain: `LlmConfig` (per-surface `{backend, model}`, `reasoner_enabled` flag) persisted at `state_path("llm_config.json")` like `desk_mode.py` (explicit, never inferred); env seed `QLAB_LLM_BACKEND`/`QLAB_LLM_MODEL`; `POST /api/llm` (validates against the catalog, records an `llm.config_changed` event, returns explanatory payload); `GET /api/llm/backends` (catalog: each backend × models with `available` + `reason`); `llm` block on `/api/tui`. Registry(":memory:") tests incl. refusing an uncataloged choice with the catalog's reason.
- **A3 — routing backend extension.** `model_routing.py`: backend joins the route (`TIER_MODEL` stays; `resolve_route` consults `llm_config.workforce` for non-required roles; `REQUIRED_CLAUDE_ROLES` pins referee to claude regardless, with a `fallback_reason` the audit trail records); `record_invocation(backend=...)` flows the real backend. Tests: referee immovability; route rows carry backend.
